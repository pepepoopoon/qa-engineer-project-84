# Тестирование интернет-магазина

Учебный QA-проект в рамках курса Хекслета. Цель проекта — провести ручное функциональное тестирование интернет-магазина, проверить соответствие требованиям, выявить дефекты и выполнить регрессионное тестирование после обновления приложения.

## Выполненная работа

- Проанализированы функциональные, нефункциональные и неявные требования к интернет-магазину.
- Разработаны тест-кейсы для проверки каталога товаров, поиска, фильтрации, карточек товаров и корзины.
- Проведено ручное тестирование основных пользовательских сценариев.
- Подготовлен отчёт о прохождении тест-кейсов.
- Обнаруженные дефекты оформлены в виде баг-репортов с шагами воспроизведения, ожидаемыми и фактическими результатами.
- Проведено регрессионное тестирование обновлённой версии приложения.

## Инструменты

- Google Chrome и Chrome DevTools
- Git и GitHub
- YAML для оформления тестовой документации
- GitHub Actions для автоматической проверки структуры проекта

## Содержание репозитория

| Файл | Описание |
|---|---|
| `about.yml` | Информация о тестировщике |
| `requirements.yml` | Функциональные, нефункциональные и неявные требования |
| `test-cases.yml` | Тест-кейсы с шагами и ожидаемыми результатами |
| `testing-report.yml` | Результаты первичного тестирования |
| `bugreports.yml` | Описание выявленных дефектов |
| `regress-report.yml` | Результаты регрессионного тестирования |
| `assets/` | Скриншоты обнаруженных ошибок |

## Тестируемые приложения

- Первая версия: https://products-store.hexlet.app/
- Вторая версия: https://products-store-v2.hexlet.app/

## Результаты регрессии

Во второй версии выполнено 28 тест-кейсов: 13 pass, 15 fail.
Исправлены сброс выбранной категории и кликабельная область карточки товара.
Частично исправлены переход по хэштегу категории и мобильная вёрстка.
Сохранились ошибки фильтрации, расчёта суммы, оформления заказа, рейтинга в каталоге,
закрытия окна заказа и сохранения очистки корзины после обновления страницы.
Три новых дефекта описаны в `regress-report.yml`.

## Автоматическая проверка

Проверка структуры проектных файлов запускается через GitHub Actions при обновлении репозитория.
